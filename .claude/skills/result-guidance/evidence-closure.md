# Evidence for figures and reports

Use only the current task's authenticated source packet. Start from the question, observable, units, conditions and a comparison the available data can actually support. Keep computed values attached to the original table row or structured fact; preserve original precision in source files. Treat file paths, hashes and job identifiers as provenance rather than scientific measurements.

Inspect the accessible original data, documents and applicable skill guidance for the task. Prefer an existing capability when it fits; otherwise independently design, write and check Python analysis or plotting code in the sandbox, with no fixed analysis or chart template. The model chooses the method and code; the sandbox tool provides isolated execution, read-only input and guidance files, and preserves outputs and failure evidence. Isolation and source, output, visual and scientific checks remain in force.

For data-sandbox code, read each selected source at its `/inputs` sandbox path. Write declared data files directly under `/output` using their declared names; the host publishes them under the approved output directory's `artifacts` subdirectory. A downstream node may bind a required typed JSON property by its producer, output index and JSON Pointer. Omit the duplicate literal target argument; do not claim a downstream tool supplied a value before it has actually run. User-approved scientific constraints and the consumer schema still apply.

For a figure, identify source columns and units for each panel. Distinguish raw data from derived quantities; state any transformation, uncertainty propagation, and assumptions. If the source does not establish an uncertainty or a sample count, mark it unknown instead of inventing it. Review the actual rendered image and preserve any author or reviewer limitations. Visual verification concerns the supplied pixels and sources; it is not independent scientific validation.

For a report, use source, table, figure and literature identifiers only for their declared roles: a figure ID is not a literature reference. Select native fact blocks for structured operational or input facts and use native table/measurement blocks for numbers; do not copy machine identifiers into narrative as measurements. Retain complete source tables and describe a figure with its source and applicable limitations. Cite literature only when the packet contains the corresponding evidence; a bibliographic record alone cannot establish an unsupported quantitative claim.

Separate execution success, solver or statistical convergence, agreement between models, and physical validation. Preserve unknowns and unresolved assumptions next to the conclusion they affect. State the scope of each comparison and avoid inferring unmeasured physics, sample independence, or a new result from a plot title. If current evidence cannot support a required claim, report the gap and the useful next check rather than silently filling it.

This short project guidance is adapted from the research-tech-report, scientific-figures and credible-computational-pipeline skill principles. It does not grant tool, scheduler, publication, or scientific acceptance authority.
