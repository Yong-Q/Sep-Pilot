# LLM result plotting in an OS sandbox

The analyst/communicator writes task-specific Python, reads actual owned CSVs,
and calls `plot_result_code`. Plot types and layouts are chosen by the agent;
there is no fixed chart template. New attempts use new output directories.
The normal DAG tool node depends on actual result-table producers and declares
its PNGs and `manifest.json`; the report node then depends on that plot node.

`read_result_guidance` loads only selected, hash-verified Nature figure/writing
pages. The roles' always-loaded router is small; no figure/backend gate runs for
ordinary status chat. Python is the user's explicit default; an explicit R
request is respected, but this first native executor is Python-only and does not
pretend to execute R. Selected guidance may be staged read-only with
`guidance_files`; the LLM reads guidance via a native read tool, not by claiming
the remote model itself runs inside the process sandbox.

## Isolation and bounds

Linux x86-64 compute allocation only. The trusted launcher uses user, mount,
PID, IPC and network namespaces; tmpfs root, read-only system/Python runtime, script
and input snapshots; chroot; no capabilities; no-new-privileges; seccomp denies
process creation/exec, sockets, SysV/POSIX message-queue IPC, ptrace, mount and namespace changes. Only
same-process thread creation is permitted for matplotlib; clone3 returns
ENOSYS so libc can use checked clone flags. No project source, account state or
other conversation is mounted. It is an OS process boundary, not a VM or a
promise against kernel vulnerabilities or a hostile writer with the same host
UID. Trusted code/runtime installation remains operator-controlled.

The script runs for 1–60 seconds with CPU, 2 GiB virtual-address-space and
16 MiB per-file limits; output and temporary tmpfs mounts are 32 MiB each,
root tmpfs is 96 MiB (all charged to the allocation's RAM). Input CSVs are
bounded to 8 MiB each / 16 MiB total, at most 8 tables / 10,000 rows / 128
columns. The namespace parent copies only 1–8 verified regular PNGs, at most
4096×4096 pixels, after the child stops. The launcher process tree is killed
and drained on outer timeout/cancellation. No fallback to unrestricted Python.
node05 real namespace/render/attack tests are required; a temporary directory
alone or login-node bwrap availability does not establish compute isolation.

## Evidence and limitations

Retained: exact script, read-only input snapshots, unit/method/missing/nonfinite
audits, selected guidance and SHA, implementation SHA, exit/timeout and logs,
PNG size/content hashes and manifest. Unit declarations are caller-supplied,
not independently proved by a column name. No missing data is automatically
filled or science value generated by native code. The agent must label source,
units, method and partial/nonconverged status and review its actual chosen code.
Different methods or units must not be silently treated as identical.

The result is `rendered_needs_review`, `scientific_acceptance=false` and
`sandbox_derived_unverified`: image integrity is not a scientific or visual
judgement. There is currently no PNG-to-provider-image bridge; visual review
stays explicitly pending. Later owner-auth image loading must bind current
session, exact artifact SHA and provider image capability; a text-only provider
must report unsupported. No current download or vision capability is invented.

Scripts are reusable; old plots are not cached. Input/script/implementation
identities are recorded, but arbitrary imports, fonts and randomness are not a
complete operator-locked runtime. The dedicated fingerprint returns None and
parallel execution cannot fall back to a coarse cache. Every new plot attempt
requires a fresh output directory, preserving earlier results and failures.
